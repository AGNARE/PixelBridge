# PixelBridge — Web → Figma Bridge

Собственный плагин для Figma Desktop, который переносит веб-страницы и
HTML/CSS-код в редактируемые слои Figma, плюс постоянный мост, через который
дизайн в ваш холст строит **ИИ-агент**.

> Репозиторий: <https://github.com/AGNARE/PixelBridge> ·
> локальная папка проекта: `figma-web-capture` · плагин в меню Figma:
> **Web → Figma Bridge**

**Безлимитно и бесплатно.** Никаких аккаунтов, подписок, лимитов и телеметрии:
страницу рендерит ваш собственный Chrome на вашем компьютере. **Нулевые
зависимости** — нужен только Node.js, который у вас уже есть. `npm install`
не требуется.

Работает в двух режимах:

| Режим | Кто ведёт | Как |
|---|---|---|
| **Руками** | вы, как UX/UI-дизайнер | интерфейс плагина: вставили адрес → получили редактируемый макет |
| **Через ИИ** | агент (Claude, GPT, Cursor, DSH — любой, умеющий HTTP) | локальный мост на `127.0.0.1:7331` + скиллы из `skills/` |

## Как это устроено

```
   сайт ──CDP──┐
                ├──►  IR  ──►  плагин Figma  ──►  слои
   агент ─HTTP─┘
```

**IR** (Intermediate Representation) — единое нормализованное дерево: тип слоя,
геометрия, вычисленные CSS-стили, текст, картинки, порядок отрисовки. Его
собирает либо парсер веб-страницы, либо агент. Дальше путь один и тот же —
поэтому страница с сайта и макет от ИИ кладутся на холст одинаково.

Рендерит **настоящий Chrome** через Chrome DevTools Protocol, а конкретно
`DOMSnapshot.captureSnapshot` — внутренний механизм браузера, который отдаёт
уже **вычисленные** стили и координаты каждого узла. Это не парсинг CSS
своими руками, а те же данные, которыми пользуется сам Chrome при отрисовке.

| Компонент | Что делает |
|---|---|
| `engine/cdp.js` | клиент Chrome DevTools Protocol на встроенном `WebSocket` |
| `engine/browser.js` | запуск Chrome/Edge, три режима профиля |
| `engine/capture.js` | подготовка страницы, снапшот, SVG, картинки, шрифты |
| `engine/serialize.js` | снапшот → IR, склейка текстовых рунов, семантика слоёв |
| `engine/validate.js` | ловит вырожденные боксы и потерянные ассеты |
| `engine/ws.js` | WebSocket-сервер по RFC 6455, написан вручную |
| `engine/server.js` | HTTP-маршруты и мост к плагину |
| `code.js` | плагин: IR → слои Figma, авто-лейаут, шрифты, градиенты |
| `ui.html` | интерфейс плагина и адаптер моста |
| `skills/` | скиллы для ИИ-агента: роль дизайнера и работа с мостом |

## Установка

Три шага, каждый — один раз.

### 1. Движок

Двойной клик по **`start-engine.cmd`**. Откроется окно с журналом.

Проверить, что всё поднялось: откройте <http://127.0.0.1:7331> в браузере —
увидите страницу состояния и журнал. Или `curl http://127.0.0.1:7331/health`.

> Окно движка должно быть открыто, пока вы работаете с плагином. Оно живёт
> отдельным процессом и не зависит от чата с агентом — один движок обслуживает
> и вас, и любую сессию ИИ.

### 2. Плагин

В Figma Desktop:

1. Меню **Plugins → Development → Import plugin from manifest…**
2. Выберите файл **`manifest.json`** из этой папки
3. Запустите плагин: **Plugins → Development → Web → Figma Bridge**

Плагин появится в списке разработки. При следующих запусках Figma он
останется там — импортировать заново не нужно.

### 3. Скиллы (только если работаете с ИИ-агентом)

```
install-skills.cmd
```

Копирует `skills/figma-bridge` и `skills/ux-ui-design` в
`%USERPROFILE%\.dsh\skills\` и `%USERPROFILE%\.agents\skills\`. Подробнее —
в разделе [Скиллы для агента](#скиллы-для-агента).

### 4. Проверка

Откройте плагин. В шапке должен загореться **зелёный индикатор**, а в журнале
появиться строка «Плагин запущен. Движок: http://127.0.0.1:7331».

Если индикатор жёлтый — движок не запущен, вернитесь к шагу 1.

## Режим 1: руками, как дизайнер

### Импорт сайта по ссылке

1. Вкладка **«Сайт»**
2. Вставьте адрес, например `https://tailwindcss.com`
3. Отметьте размеры экрана — можно несколько сразу, получите адаптивные
   фреймы рядом друг с другом: **1440 / 1280 / 768 / 390** или своя ширина
4. **«Импортировать в Figma»**

Фрейм появится на холсте и будет выделен.

### Импорт кода

1. Вкладка **«Код»**
2. Вставьте HTML и CSS
3. **«Импортировать код в Figma»**

Код рендерится в настоящем Chrome через локальное превью — со всеми
вычисленными стилями, а не «на глаз».

### Настройки импорта

| Параметр | Что делает |
|---|---|
| **Профиль браузера** | `изолированный` — каждый раз чистый; `постоянный` — логины сохраняются между запусками; `ваш профиль Chrome` — закрытые страницы под вашей сессией |
| **Раскладка** | `умная` — авто-лейаут там, где он точно воспроизводит раскладку; `абсолютные координаты` — пиксель-в-пиксель; `агрессивная` — авто-лейаут везде, где возможно |
| **Автовысота текста** | высота текстовых слоёв подстраивается под содержимое |
| **Описания слоёв** | подсказки из `alt`, `aria-label`, `placeholder` в аннотации Figma |
| **Трассировка к коду** | CSS-селектор и адрес источника в данных слоя |
| **Догружать ленивые картинки** | прокрутка страницы перед снятием, чтобы подгрузились изображения ниже сгиба |
| **Масштаб теней** | Figma визуально расширяет тень сильнее CSS. Если тени кажутся крупнее — переключите на половину |

### Профиль под авторизацией

Выберите в настройках **«Постоянный»**. При первом запуске откройте страницу
и войдите вручную — сессия сохранится в папке `engine/.profile`, и дальше
закрытые страницы будут захватываться без повторного входа.

> Папка `engine/.profile` содержит куки и сессии. Она в `.gitignore` и никуда
> не отправляется — см. [Приватность](#приватность).

## Режим 2: через ИИ-агента

Пока окно плагина открыто, движок может строить слои у вас на холсте. Это то,
чего не умеет официальный Figma MCP: REST API Figma **не создаёт узлы** —
писать в холст может только плагин, и он у нас есть.

Агент работает по циклу **построил → посмотрел → исправил**: он не видит
Figma, поэтому после каждой сборки делает скриншот и смотрит на него картинкой.

### Проверка перед работой

```bash
curl http://127.0.0.1:7331/health
```

`{"ok":true,"plugin":true}` — можно работать. `plugin:false` — окно плагина
закрыто, попросите пользователя открыть его. **Без открытого окна плагина не
работает ничего**: именно плагин держит WebSocket к движку.

### Собрать дизайн

```bash
curl -X POST http://127.0.0.1:7331/api/build \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Экран входа",
    "width": 1440, "height": 900,
    "background": "#0f172a",
    "nodes": [{
      "type": "frame", "name": "Карточка",
      "box": [520, 290, 400, 320],
      "style": { "background": "#ffffff", "radius": 16,
                 "boxShadow": "0 12px 32px rgba(0,0,0,.25)", "padding": 32 },
      "children": [
        { "type": "text", "name": "Заголовок", "text": "Вход в аккаунт",
          "box": [32, 32, 336, 40],
          "style": { "fontSize": 28, "fontWeight": 700, "color": "#0f172a" } }
      ]
    }]
  }'
```

`box` — `[x, y, width, height]` **относительно родителя**. `type` — `frame`,
`text`, `image`, `svg` или `input`.

### Захватить сайт и сразу собрать

```bash
curl -X POST http://127.0.0.1:7331/api/capture-and-build \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com","width":1440}'
```

### Посмотреть результат

```bash
curl -X POST http://127.0.0.1:7331/api/screenshot \
  -H "Content-Type: application/json" \
  -d '{"nodeIds":["1:23"],"scale":1}'
```

Файл PNG сохранится в `engine/.cache/shots/`, путь вернётся в ответе — агент
читает его своим инструментом работы с картинками. Так и замыкается цикл.

### Все маршруты

| Метод | Маршрут | Назначение |
|---|---|---|
| `POST` | `/api/capture` | `{"url":"…","width":1440}` → IR |
| `POST` | `/api/capture-code` | `{"html":"…","css":"…","width":1440}` → IR |
| `POST` | `/api/capture-and-build` | захват и сразу сборка в Figma |
| `POST` | `/api/build` | `{"name":"…","nodes":[…]}` → слои |
| `POST` | `/api/screenshot` | `{"nodeIds":["1:2"],"scale":1}` → PNG |
| `POST` | `/api/select` | `{"nodeIds":[…]}` — выделить слои |
| `POST` | `/api/delete` | `{"nodeIds":[…]}` — удалить слои |
| `GET` | `/api/state` | имя файла, страница, выделение, слои холста |
| `GET` | `/api/selftest` | проверка возможностей Figma |
| `GET` | `/health` | состояние движка и плагина |
| `GET` | `/asset/<сессия>/<id>` | байты картинок |
| `GET` | `/proxy?url=…` | картинка по внешнему URL без CORS |
| `GET` | `/` | страница состояния с журналом |
| `GET` | `/ui` | интерфейс плагина в браузере (для отладки) |

### Свойства стиля в `/api/build`

Ключи можно писать как в CSS (`font-size`, `border-top-color`), так и коротко
(`fontSize`, `radius`, `background`, `border: "1px solid #ccc"`, `padding`,
`boxShadow`, `display`, `flexDirection`, `justifyContent`, `alignItems`,
`lineHeight`, `letterSpacing`, `textAlign`, `gap`). Числа автоматически
получают `px`. `box` принимает и объект `{x,y,w,h}`, и массив `[x,y,w,h]`.
`src` у `image` принимает `http(s)`-адрес — движок проксирует его сам, CORS
не ваша забота.

### Пример: агент, который рисует сам

Минимальный сценарий для любого языка, умеющего HTTP. Агент описывает экран
деревом и получает путь к картинке:

```python
import json, urllib.request

BRIDGE = "http://127.0.0.1:7331"

def post(path, body):
    req = urllib.request.Request(BRIDGE + path,
                                 data=json.dumps(body).encode("utf-8"),
                                 headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=900) as r:
        return json.loads(r.read().decode("utf-8"))

def get(path):
    with urllib.request.urlopen(BRIDGE + path, timeout=180) as r:
        return json.loads(r.read().decode("utf-8"))

# 0. мост жив?
assert get("/health")["plugin"], "Откройте окно плагина в Figma"

# 1. построить
post("/api/build", {
    "name": "Дашборд",
    "width": 1440, "height": 900, "background": "#F4F6F8",
    "nodes": [{
        "type": "text", "name": "Заголовок", "text": "Проекты",
        "box": [64, 48, 400, 48],
        "style": {"fontSize": 32, "fontWeight": 700, "color": "#0F172A"},
    }],
})

# 2. найти, что создалось
node_id = get("/api/state")["selection"][0]["id"]

# 3. посмотреть своими глазами
shot = post("/api/screenshot", {"nodeIds": [node_id], "scale": 0.5})
print("смотреть сюда:", shot["shots"][0]["file"])
```

Дальше агент читает PNG, видит, что «поехало», и повторяет шаги 1–3.

### Пример: интеграция как инструмент агента

Если ваш агент умеет объявлять инструменты (function calling), мост
оборачивается в три функции — этого достаточно для полноценной работы:

```json
[
  { "name": "figma_build",
    "description": "Нарисовать экран в Figma. Возвращает report со статистикой и причинами отказа от авто-лейаута.",
    "parameters": { "type": "object",
      "properties": { "name": {"type":"string"}, "width": {"type":"number"},
                      "height": {"type":"number"}, "background": {"type":"string"},
                      "nodes": {"type":"array","items":{"type":"object"}} },
      "required": ["name","nodes"] } },

  { "name": "figma_state",
    "description": "Прочитать состояние файла: имя, страница, выделение, слои холста с id.",
    "parameters": { "type": "object", "properties": {} } },

  { "name": "figma_screenshot",
    "description": "Экспортировать слои в PNG и вернуть путь к файлу, чтобы посмотреть результат.",
    "parameters": { "type": "object",
      "properties": { "nodeIds": {"type":"array","items":{"type":"string"}},
                      "scale": {"type":"number"} },
      "required": ["nodeIds"] } }
]
```

Пример для Claude Code / Cursor / любого агента с shell-доступом — то же самое
через `curl`:

```bash
# построить
curl -s -X POST http://127.0.0.1:7331/api/build -H "Content-Type: application/json" -d @screen.json

# узнать id созданного
curl -s http://127.0.0.1:7331/api/state

# посмотреть
curl -s -X POST http://127.0.0.1:7331/api/screenshot -H "Content-Type: application/json" -d '{"nodeIds":["1:23"],"scale":0.5}'
```

Ничего специфичного для конкретного агента здесь нет: это обычный HTTP на
`localhost`. Работает из Claude Code, Cursor, Windsurf, LangChain, n8n, вашего
собственного скрипта — и из DSH, для которого скиллы уже написаны.

### Что агент обязан прочитать перед первой сборкой

Три правила, на которых чаще всего теряется редактируемость:

1. **`box` ребёнка — относительно родителя**, не от корня. Координаты от корня
   переводят *каждый* контейнер в абсолютные слои: одна сборка потеряла так
   82 контейнера из 82.
2. **Высота текста должна быть точной:** `строк × round(кегль × 1.35)`, а
   переносы — явными `\n`. Плагин ставит `textAutoResize = HEIGHT`, Figma
   перемеряет текст, и угаданная высота разъезжается со всей раскладкой.
3. **Не считать боксы руками.** Возьмите `skills/figma-bridge/layout-engine.py` —
   он считает размеры из содержимого и помечает растяжимые элементы, поэтому
   сборка выходит на 100 % редактируемым авто-лейаутом.

Полный список — в `skills/figma-bridge/ПРАКТИКА.md`, там же замеры и способы
отладки.

## Скиллы для агента

Скиллы — это рабочие инструкции для модели, а не документация для человека.
Они лежат в репозитории (`skills/`) и устанавливаются одной командой:

```
install-skills.cmd
```

| Скилл | Роль | Что даёт |
|---|---|---|
| [`skills/ux-ui-design/`](skills/ux-ui-design/SKILL.md) | **дизайнер** | бриф, исследование, информационная архитектура, каркас, токены, состояния, доступность, передача. Чек-листы и формат обоснования решений |
| [`skills/figma-bridge/`](skills/figma-bridge/SKILL.md) | **инструмент** | маршруты моста, цикл «построил → посмотрел → исправил», движок раскладки, правила геометрии, известные ограничения |

`ux-ui-design` отвечает на вопрос **что** рисовать, `figma-bridge` — **как**
положить это на холст, не потеряв редактируемость. Вместе они дают то, чего
не даёт ни один генератор картинок: решения с причинами, отрисованные в вашем
рабочем файле настоящими слоями и компонентами.

Куда устанавливается: `%USERPROFILE%\.dsh\skills\` и
`%USERPROFILE%\.agents\skills\`. Агент видит новый скилл сразу — перезапуск
не нужен. Если положить папку `skills` внутрь проекта, работают ещё
`<проект>/.dsh/skills` и `<проект>/.agents/skills`.

Формат — каталог с файлом `SKILL.md`, начинающимся с YAML-заголовка, по
которому агент решает, доставать скилл или нет:

```markdown
---
name: figma-bridge
description: Когда применять этот скилл.
---
```

**Дополняйте `ПРАКТИКА.md` после каждой сессии.** Что удивило, обо что
споткнулись, какой приём сработал — туда, в репозиторий, и
`install-skills.cmd` заново. Скилл без поддержки начинает врать через месяц.

## Приватность

Проект локальный **по конструкции**, а не по обещанию.

| Что | Куда уходит |
|---|---|
| Страницы, которые вы импортируете | никуда — их рендерит ваш Chrome на вашей машине |
| Слои, дизайны, текст | никуда — плагин пишет прямо в открытый файл Figma через официальный Plugin API |
| Скриншоты и картинки | в `engine/.cache/`, локальная папка |
| Логины и сессии сайтов | в `engine/.profile/`, локальная папка, только если вы сами выбрали профиль «постоянный» |
| Ключи, токены, пароли | **проект их не использует.** Ни одной переменной с секретом: движок слушает `127.0.0.1`, плагин общается с движком по WebSocket на той же машине |

Наружу движок ходит ровно за двумя вещами: за страницей, которую вы попросили
импортировать, и за картинками с этой страницы. Всё.

Что проверено и вынесено из репозитория:

- Секретов в коде нет — проверено поиском. Единственные совпадения оказались
  ложными: `--password-store=basic` (флаг запуска Chrome) и переменная
  `token` в парсере градиентов.
- `.gitignore` исключает `.cache/`, `engine/.cache/`, `engine/.profile/`,
  `__pycache__/`, `node_modules/`, `*.pem`, `*.key`, `.env`, `Cookies`,
  `Login Data` и прочее, что может содержать чужие данные.
- Движок **не содержит** аналитики, автообновлений и обратных вызовов на
  внешние адреса. Зависимостей нет вообще (`"dependencies": {}`), поэтому
  нечего и подтягивать.
- REST API Figma и официальный Figma MCP здесь не используются, доступ к
  аккаунту не запрашивается: всё идёт через плагин, запущенный вами вручную.

Единственный сетевой порт — `127.0.0.1:7331`, он слушает только локальный
интерфейс. Порт меняется переменной `W2F_PORT`.

## Что переносится

- **Раскладка** — flex, блочные контейнеры и **grid** превращаются в настоящий
  авто-лейаут Figma там, где он воспроизводит геометрию точно. Это не догадка:
  плагин предсказывает раскладку сам и сверяет с реальными координатами из
  браузера, и включает авто-лейаут только при совпадении. Остальное —
  абсолютные координаты (пиксель-в-пиксель).
- **Внешние отступы у детей flex-контейнера** — выражаются рамкой-обёрткой,
  у которой padding равен отступам. Авто-лейаут Figma не умеет `margin`,
  но `padding` обёртки даёт ровно ту же геометрию.
- **Текст** — семейство, вес, наклон, размер, межбуквенное расстояние,
  межстрочный интервал, выравнивание, регистр, подчёркивание, переносы `<br>`.
  Смешанные стили внутри абзаца — через диапазоны Figma.
- **Картинки** — цвет, линейные и радиальные градиенты, картинки с
  `cover`/`contain`. **AVIF и SVG перекодируются** в PNG или JPEG: Figma
  `createImage` понимает только PNG, JPEG и GIF. Без этого на `formula1.com`
  терялось 65 картинок из 76 — теперь ноль. Прозрачность решает формат:
  есть альфа — PNG, нет — JPEG, чтобы фотографии не раздувались.
- **Границы** — толщина по сторонам, цвет, `solid`/`dashed`/`dotted`.
- **Скругления**, **тени** (внешние и внутренние), **свечение**, **размытие**.
- **Прозрачность**, **поворот**, **обрезка по `overflow`**.
- **Встроенный SVG** — строится вектором из разметки.
- **Псевдоэлементы** `::before` / `::after` — как обычные слои.
- **Имена слоёв** — из семантики: `.card «Заголовок карточки»`.
- **Описания** — `alt`, `aria-label`, `placeholder`, `title` в аннотации слоя.
- **Трассировка** — CSS-селектор слоя в данных плагина, до разработчика.
- **Порядок слоёв** — по реальному порядку отрисовки браузера, с учётом `z-index`.

## Ограничения

Честный список того, что не переносится или переносится приблизительно:

- **`display: grid` с неравными дорожками.** Дорожки grid-лейаута Figma —
  это равные доли фрейма. Поэтому `grid-columns: 1fr 2fr` или `120px 200px`
  раскладывается абсолютными координатами: геометрия точная, но
  редактируемого grid-лейаута в этом случае не будет. Равные дорожки
  (`1fr 1fr`, `repeat(3, 1fr)`) переносятся полноценным GRID-лейаутом,
  включая объединение ячеек через `grid-column: span N`.
- **Внешние отступы у детей блочного контейнера.** В блочной раскладке
  отступы соседних элементов схлопываются, и сумму выразить нельзя —
  такой контейнер уходит в абсолютные координаты. У flex-контейнеров
  схлопывания нет, там отступы переносятся точно.
- **Авто-отступы** (`margin: auto`) — распределяют свободное место, модель
  авто-лейаута Figma такого не выражает.
- **Прокручиваемые области** — показывается видимая часть, содержимое за
  границей обрезки не разворачивается.
- **`position: fixed`** — укладывается обычным слоем в общий поток, а не
  отдельным оверлеем.
- **`transform` со сжатием или наклоном** — переносится только чистый поворот.
- **Скриншот страницы не подкладывается фоном.** Слои строятся векторно;
  растровая подложка для «сложных» мест (canvas, WebGL) не делается.
- **Конические градиенты** (`conic-gradient`) и CSS-фильтры кроме `blur()`
  не переносятся.
- **Шрифты.** Если браузер использовал шрифт, которого нет в Figma, берётся
  ближайший доступный. Плагин сообщает об этом в отчёте.
- **Картинки, которые браузер так и не загрузил.** Страницы с бесконечной
  лентой подгружают изображения по мере прокрутки. Захват прокручивает
  страницу целиком (до 50 000 px), но то, что не загрузилось и после этого,
  перенести нечем. Плагин пишет в отчёте, сколько картинок не нашлось.
  Тела изображений забираются через CDP (`Network.getResponseBody`), где
  ограничения CORS не действуют, — поэтому чужие CDN не мешают.
- **Время захвата.** Тяжёлая страница — от 5 до 30 секунд. Больше всего времени
  уходит на прокрутку ради ленивых картинок; это отключается галочкой
  «Догружать ленивые картинки».

**Про семантику `layoutPositioning = 'ABSOLUTE'`.** В Figma абсолютные дети
авто-лейаут-фрейма позиционируются относительно рамки фрейма. Плагин
пользуется этим, но включает авто-лейаут с абсолютными детьми **только когда
у контейнера нет padding** — тогда оба возможных толкования совпадают, и
результат верен в любом случае.

## Тесты

```
run-tests.cmd
```

Или по одному:

```bash
node test/test-serialize.js       # геометрия IR против getBoundingClientRect
node test/test-converter.js       # дерево Figma против IR
node test/test-code-and-agent.js  # импорт кода и агентская сборка целиком
node test/test-image-normalize.js # AVIF/SVG → PNG/JPEG
node test/test-grid-unsupported.js# деградация, когда Figma не умеет GRID
node test/test-converter-big.js https://tailwindcss.com/   # тяжёлая страница
node test/test-server.js          # мост с поддельным плагином
node test/test-ui.js              # интерфейс в headless Chrome
node test/test-visual.js          # визуальная сверка: IR → HTML → сравнение с оригиналом
node test/profile-build.js        # профиль сборки в живой Figma (нужен открытый плагин)
```

Чем эти тесты отличаются от «код не упал»:

- **Мок Figma API намеренно строгий.** Он бросает исключение, если шрифт
  не загружен, а текст уже пишется; если SVG битый; если `resize` вызван
  у текста с авто-шириной; если якоря grid-лейаута проставлены до добавления.
  Мягкий мок доказывал бы только отсутствие падений.
- **Геометрия сверяется с живым DOM.** Тест реконструирует абсолютные
  координаты обходом IR и сравнивает с `getBoundingClientRect`.
- **Дерево Figma сверяется с IR.** Авто-лейаут в моке реализован независимо,
  поэтому совпадение координат — не тавтология.
- **Корневые причины отделены от каскадных.** Если родитель разъехался,
  его дети не засчитываются как новые ошибки.
- **Визуальная сверка.** IR отрисовывается обратно в HTML, снимается
  скриншот и сравнивается с оригиналом попиксельно. Это ловит то, чего
  не видят структурные тесты: потерянный слой, сбитый порядок наложения,
  пропавшую прозрачность. Отдельно считается «структурное» расхождение —
  та же сверка в уменьшенном масштабе, где рябь сглаживания шрифтов
  усредняется, а ошибки макета остаются.
  Тест проверяет и сам себя: убирает один слой и убеждается, что метрика
  ухудшилась.
- **Мок повторяет поведение настоящей Figma.** Первый же реальный импорт
  упал на `layoutPositioning = 'INHERIT'` — недопустимом значении, которого
  мок не заметил. Теперь мок строго проверяет перечисления и отвергает
  недопустимые значения.

## Что дала проверка в настоящей Figma

Плагин нельзя прогнать в Figma на этапе разработки, поэтому в него встроена
**самопроверка возможностей**: кнопка «Проверить возможности Figma» в
интерфейсе или `GET /api/selftest`. Она прогоняет каждую используемую
возможность на временном фрейме и сообщает результат.

Что она выяснила и что из этого последовало:

| Находка | Что сделано |
|---|---|
| `layoutPositioning` принимает только `AUTO`/`ABSOLUTE` | исправлено, добавлена проба в самопроверку |
| `layoutMode = 'GRID'` работает, но **якоря ячеек — нет** | grid проверяется до сборки целиком; без якорей сетки ложатся абсолютно |
| Сборка 400 слоёв занимала **226 секунд** | убрана отдача управления через `setTimeout` — Chrome душит таймеры скрывшихся окон. Стало **4,7 секунды** |
| Провалившийся импорт оставлял мусор на холсте | неудачная сборка убирает за собой |
| Шрифт, который не удалось загрузить, ронял весь импорт | неподходящий шрифт подставляется, импорт продолжается |
| AVIF и SVG не принимаются `figma.createImage` | картинки перекодируются в PNG/JPEG тем же браузером |

Контрольные замеры в живой Figma: `example.com` — 391 мс,
`tailwindcss.com` (1563 слоя) — сборка 24,8 с, захват + передача 13 с,
`formula1.com` (933 слоя) — сборка 9,6 с.

**Важно про запускалки.** Файлы `start-engine.cmd`, `install-skills.cmd` и
`run-tests.cmd` обязаны оставаться в чистом ASCII. Проверено экспериментом:
`.cmd` с кириллицей в UTF-8 падает с `The syntax of the command is incorrect` —
и с BOM, и без него. Поэтому русские подсказки печатает Node, а не командный
файл.

> На живой странице метрика визуальной сверки зависит от сайта: если контент
> меняется между запусками (MDN, formula1.com — карусели, ленивые секции,
> видео), числа нестабильны, и это свойство сайта, а не плагина.
> Тест сам это определяет: он убирает один слой и, если метрика не шевельнулась,
> сообщает, что страница «шумная» и пороговые проверки по ней пропускает.
> Для порогов используйте синтетическую страницу по умолчанию — на ней
> 1,1% расхождения.

Наблюдения, которые дала визуальная сверка на реальных страницах:

- **`display: contents`** — элемент без собственного бокса, но с отрисованными
  детьми — раньше выбрасывался вместе с поддеревом. На MDN так терялось
  **160 слоёв** и видимая картинка.
- **`scroll-behavior: smooth`** — возврат страницы наверх превращался в
  анимацию, снимок делался посреди движения, и липкая шапка MDN оказывалась
  в IR на `y = 649` вместо своего места.
- **Скриншот снимался в конце захвата**, через 10–15 секунд после снимка.
  На formula1.com за это время успевал появиться баннер cookie-согласия,
  и сверка показывала расхождение там, где IR был прав. Теперь скриншот
  снимается сразу после снимка.

Контрольная точка на `tailwindcss.com` (тяжёлая страница, 10 345 px):
1 563 слоя, 34/34 картинки, 64/64 SVG, 161 псевдоэлемент,
**69% контейнеров с редактируемым авто-лейаутом** (из них 43 — настоящий
GRID-лейаут Figma), **ноль расхождений геометрии**, построение ~570 мс.

Ещё проверено на `developer.mozilla.org` (**366 слоёв**, структурное
расхождение визуальной сверки 1.3–7%, в зависимости от того, меняется ли
контент между запусками) и `vercel.com` (440 слоёв, 0 расхождений геометрии).

## Если что-то не работает

**Индикатор жёлтый, «движок не запущен»**
Запустите `start-engine.cmd`. Проверьте <http://127.0.0.1:7331>.

**Агент говорит, что мост недоступен**
Две независимые вещи должны быть живы: процесс движка **и** открытое окно
плагина в Figma. Проверьте <http://127.0.0.1:7331/health>: `ok:false` — не
запущен движок, `plugin:false` — не открыт плагин. Движок живёт отдельным
процессом и не привязан к чату, поэтому одна сессия агента его не «держит».

**«Не найден Chrome или Edge»**
Укажите путь вручную:
```
set W2F_BROWSER=C:\путь\к\chrome.exe
start-engine.cmd
```

**Режим «ваш профиль Chrome» не запускается**
Chrome уже открыт и держит профиль. Закройте его либо используйте режим
«постоянный» — он для этого и сделан.

**Порт 7331 занят**
```
set W2F_PORT=7444
start-engine.cmd
```
Затем откройте плагин и в журнале интерфейса адрес движка останется старым —
для смены порта откройте `ui.html` в браузере как
`http://127.0.0.1:7444/ui?engine=http://127.0.0.1:7444`.

**Слои появились, но текст «поехал»**
В настройках выключите «Автовысота текста» — тогда текстовые слои получат
ровно те боксы, что были в браузере.

**Тени выглядят крупнее, чем на сайте**
Кнопка «Переключить масштаб теней» в настройках.
