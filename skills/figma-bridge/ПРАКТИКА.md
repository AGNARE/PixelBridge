# Мост Web → Figma: практика

Всё, что выяснилось на живой работе. Читать **до** первой сборки: половина
пунктов — это грабли, на которые уже наступали.

> **Этот файл пополняется.** После каждой сессии работы с мостом дописывать сюда
> всё, что стоило времени: непонятное поведение, найденные ограничения, удачные
> приёмы. Навык без пополнения устаревает за месяц и снова начинает врать.

---

## 1. Геометрия: четыре правила

**Координаты детей — относительно родителя, не от корня.** Мост сравнивает
присланные координаты с тем, что дал бы flex. Накопленное смещение от корня даёт
расхождение в сотни пикселей, и тогда **все** контейнеры падают в абсолютные слои:
дизайн получается, но перестаёт быть редактируемым. Один раз так потерял 82 контейнера.

**Высота текста должна быть точной.** Мост ставит `textAutoResize = HEIGHT`,
поэтому Figma растягивает текст по факту. Формула: `строки × round(кегль × 1.35)`.
Многострочный текст писать явными `\n` — на перенос надеяться нельзя.

**Однострочный текст — `whiteSpace: nowrap`.** Мост фиксирует ширину и обрезает
многоточием; результат детерминирован. Иначе Figma может завернуть строку.

**`align-items` — только `center` или `flex-start`.** Значение `top` не понимает
и молча даёт другое выравнивание.

## 2. Цвет

`background-color: rgba(...)` превращается в **непрозрачный белый**. Первая сборка
тёмной темы из-за этого вышла с белой карточкой и невидимым текстом на ней.

- в **градиентах** (`backgroundImage: radial-gradient(... rgba ...)`) прозрачность
  работает — на этом держатся свечения;
- в **сплошных заливках** — нет. Тёмные темы собирать слоями сплошных цветов.

## 3. Кадры накладываются

Новый кадр ставится в центр вьюпорта, а после сборки мост делает
`scrollAndZoomIntoView`. Значит, следующий кадр ложится на предыдущий.

Решение: передавать `options: {"offset": 1560}` — тогда кадр встаёт ровно на
`предыдущий.x + 1560`, и весь набор выстраивается в ряд.

**Эндпоинта «подвинуть слой» нет.** Разложить уже собранное можно только пересборкой.

## 4. Что поддерживается

| Работает | Не работает |
|---|---|
| авто-лейаут: направление, зазор, отступы, выравнивание | **grid** — нет сеттеров якорей ячеек |
| линейные и радиальные градиенты | `rgba` в сплошной заливке |
| тени внешние и внутренние, размытие, прозрачность слоя | `justify-content` без ручного расчёта позиций |
| радиусы, в том числе по отдельным углам | `position: relative` со смещением |
| границы по сторонам, пунктир | `flex-wrap`, `order`, `float` |
| обрезка текста многоточием (`whiteSpace: nowrap`) | инлайн-дети в block-контейнере |
| SVG-разметка — **полная, с корневым `<svg>`** | SVG без корневого тега (заменится прямоугольником) |
| картинки по http(s) — движок проксирует, CORS не мешает | |
| экспорт слоя в PNG | |

## 5. Как отлаживать, когда «ничего не видно»

Эндпоинта для чтения дерева слоёв нет. Но мост можно **прогнать локально на макете
Figma** — из его же тестов:

```js
const mock = require('./test/figma-mock');
mock.install();
require('./code.js');
await mock.postToPlugin({ type: 'design', ir, options: {} });
const root = mock.figmaMock.currentPage._children.at(-1);
console.log(mock.flatten(root).filter(n => n.type === 'TEXT')[0]);
// → { name:'b1', characters:'', fills:[SOLID #172033], ... }
```

Именно так нашлась причина пустых карточек: `characters: ""` при правильном цвете —
строка текста не попадала в узел на стороне сборщика.

Спецификацию для отладки удобно выгрузить в JSON из своего сборщика и подсунуть
моку: `coerceStyle`/`coerceNode` из `engine/server.js` превращают дружелюбную
схему в IR (сокращение `padding` раскрывается, camelCase переводится в CSS).

## 6. Как получить 100% авто-лейаут

Рабочий рецепт — в [`layout-engine.py`](layout-engine.py). Суть:

1. размеры контейнеров **считать из содержимого**, а не задавать руками;
2. растяжимые элементы помечать `flex=True`, движок сам раздаст остаток;
3. координаты назначать **относительно родителя**;
4. вместо `justify-content` ставить распорку с `flex=True` — надёжнее;
5. после сборки читать `report.autoReasons` — там прямо написано, какой контейнер
   не стал авто-лейаутом и на сколько пикселей разошёлся.

Хороший результат: `autoLayout` = число контейнеров, `absolute` = 0.

## 7. documentAccess: dynamic-page — что ломается

Файлы, где у плагина стоит `"documentAccess": "dynamic-page"`, запрещают
синхронные обращения к документу. Каждое падение — с внятным текстом, но
находится по одному, поэтому список:

| Синхронно нельзя | Надо так |
|---|---|
| `figma.currentPage = page` | `await figma.setCurrentPageAsync(page)` |
| `node.children` | `await node.getChildrenAsync()` |
| `figma.variables.getLocalVariableCollections()` | `…getLocalVariableCollectionsAsync()` |
| `figma.variables.getLocalVariables()` | `…getLocalVariablesAsync()` |
| `node.vectorPaths = [...]` | `await node.setVectorNetworkAsync(...)` — или `figma.createNodeFromSvg()` |
| `figma.getNodeById(id)` | `await figma.getNodeByIdAsync(id)` |

Проверенный обход для иконок: **`figma.createNodeFromSvg(разметка)`** — этот путь
работает, векторы строятся, размеры ставятся через `resize`. Мост сам им
пользуется.

Ещё две вещи, которые выясняются только на живом файле:

- **`addMode` на бесплатном тарифе не работает**: `Limited to 1 modes only`.
  Двухрежимная коллекция переменных — платная возможность. Вместо неё —
  две коллекции и две библиотеки компонентов, по одной на тему.
- **Создание компонента и падение внутри цикла оставляют мусор**: компонент
  уже создан, а итерация прервана. Чистить надо не только наборы, но и
  одинокие компоненты и брошенные векторы.

## 8. Инстансы компонентов: три вещи, без которых не собрать экран

**Инстанс ставится по id конкретного варианта**, не по имени набора:
`{"type":"instance","componentId":"176:98"}`. Поиск по имени при
`dynamic-page` неудобен, а id берётся из карты, которую возвращает сборщик
дизайн-системы.

**Текст внутри инстанса надо подменять.** У компонента свой текст: кнопка
скажет «Кнопка», поле — «Поле ввода». Мост принимает `texts: ["Войти"]` и
заменяет текстовые слои внутри инстанса по порядку. Без этого экраны выглядят
как набор одинаковых заглушек.

**Цвет в инстансе не переопределить привязкой к переменной.** Если у текста
одновременно задан `color` и `colorVar`, переменная побеждает — и светлый текст
на тёмной панели становится тёмным и пропадает. Для элементов «вне темы»
(например, брендовая панель входа) `colorVar` надо не передавать вовсе.

**Неудачная сборка уносит прежде созданные кадры.** Мост при ошибке убирает
слои, которые считает своими, а учёт иногда захватывает и предыдущие сборки.
Один упавший кадр унёс четыре готовых экрана. Правило: после каждого падения
проверять, все ли прежние кадры на месте, и пересобирать пропавшие.

## 9. Порядок работы с мостом

```
GET  /health                     → ok:true и plugin:true, иначе ничего не выйдет
POST /api/build                  → собрать (уходит options.offset для раскладки в ряд)
GET  /api/state                  → узнать id собранного кадра
POST /api/screenshot             → снять PNG и посмотреть глазами
POST /api/delete                 → убрать пробные слои (ничего не подтверждает!)
```

**Смотреть глазами обязательно.** Утверждать «получилось красиво», не открыв
снимок, нельзя — расхождение геометрии и цвета на глаз ловится мгновенно,
а в отчёте видно не всё.

**Убирать за собой.** Пробные кадры остаются на холсте пользователя. Удалять
только то, что создал сам, и говорить, что удаляешь.

## 10. Серия кадров: где уходит время и что ломается (замеры)

**Незагруженная страница компонентов — главный тормоз.** При
`documentAccess: dynamic-page` Figma держит загруженной только текущую страницу.
Компоненты дизайн-системы лежат на своей, и каждый `createInstance` тянул её
загрузку заново. Замер: экран «Приглашение участников» (49 узлов, 14 инстансов)
собирался **149 с**, после `await figma.loadAllPagesAsync()` один раз за сессию
плагина — **2.9 с**. Тринадцать модальных окон: 40 с вместо получаса.

**Если нужная страница уже открыта, `setCurrentPageAsync` не вызывается** — и её
граф в новой сессии плагина не загружен. Тогда `appendChild` падает с
«Cannot access method `appendChild()` on a page that has not been explicitly
loaded». Страницу надо грузить явно (`await pg.loadAsync()`), а не надеяться на
переключение.

**`scrollAndZoomIntoView` + выделение кадра стоят до 120 с на кадр** с инстансами.
Для серийной сборки — `options.quiet: true`, вид не трогается. В тихом режиме
вьюпорт не двигается, поэтому кадры в ряд ставятся **накопленным** смещением
(`offset = 1560 * индекс`), а не одинаковым.

**Сборка без сторожевого таймера подвешивает плагин навсегда** — и лечится только
перезапуском плагина. Сторожевой таймер (180 с) снимает сборку с ошибкой, в которой
назван последний слой, и плагин остаётся рабочим.

**Отчёт о ходе по имени слоя.** `post({type:'progress', phase:'сборка: ' + имя})`
каждые 10 узлов плюс фазы «проверка grid», «кадр собран», «кадр на странице». Журнал
движка (`GET /` отдаёт страницу с журналом) показывает, на каком слое всё встало.
Так нашлась и медлительность: «3 с на узел» вместо «зависло».

**Мост приводил `texts` к строке.** `coerceNode` в `engine/server.js` делал
`String(v)`, а `INST` в движке раскладки — `str(t)`, поэтому словарь
`{text, color}` попадал в инстанс как текст `{'text': ...}`. Исправлено в обоих
местах: объекты проходят как есть. **После правки `engine/server.js` движок надо
перезапустить** — плагин переподключается сам; полностью перезапускать плагин не нужно.

**Сухая проверка раскладки до сборки.** Обход дерева «ребёнок шире или выше
контейнера» ловит то, из-за чего мост отказывается от авто-лейаута. На тринадцати
модалках нашлось 20 переполнений; после правок — ноль, и сборка дала `абсолютных 0`.

**Имя коллекции в имени переменной.** На бесплатном тарифе у коллекции один режим,
поэтому тем две, и имена переменных в них совпадают. Поиск по имени без коллекции
берёт случайную — формат `«Synapse Dark/color/surface»` решает это. Кэш имён надо
сбрасывать после сборки дизайн-системы, иначе он держит старый список.

**Тёмная тема — это данные, а не второй набор скриптов.** Один и тот же сборщик
собирает обе темы, если палитра, префикс коллекции и карта вариантов выбираются по
теме; карту тёмных вариантов удобно сохранять со снятым суффиксом `« · Dark»` —
тогда имена вариантов совпадают со светлыми и код не различает темы.
