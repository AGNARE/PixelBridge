# Установка — пошагово

Инструкция для человека, который получил ссылку
<https://github.com/AGNARE/PixelBridge> и у него на компьютере ещё ничего нет.

**Главное, что нужно понять сразу:** это **локальный** инструмент. Никакого
сервера в интернете нет, аккаунт не нужен, регистрация не нужна. Каждый, кто
хочет им пользоваться, **скачивает те же файлы и запускает их на своей
машине**. Ваш компьютер считает ваши страницы, ваш Figma-файл получает слои —
чужие данные при этом никуда не идут.

Отсюда следствие: переслать другому человеку **ссылку на репозиторий**, а не
папку с работающим движком. Он повторит эти же шаги у себя.

## Что понадобится

| Что | Зачем | Обязательно |
|---|---|---|
| **Figma Desktop** — приложение, не браузер | плагин ставится только в настольную версию; в браузерной нет меню **Development** | да |
| **Node.js 20 или новее** | на нём работает движок захвата | да |
| **Chrome или Edge** | страницу рендерит настоящий браузер | да, обычно уже стоит |
| Git | только для способа «через git clone»; для ZIP не нужен | нет |

Устанавливать пакеты не нужно: у проекта **ноль зависимостей**, `npm install`
не требуется. Общий размер — около 200 КБ.

## Шаг 1. Скачать файлы

Выберите любой из двух способов. Результат одинаковый.

### Способ А — ZIP, без git (проще)

1. Откройте <https://github.com/AGNARE/PixelBridge>
2. Нажмите зелёную кнопку **`Code`** → **`Download ZIP`**
3. Сохранится файл `PixelBridge-main.zip`
4. Распакуйте его — правый клик → **«Извлечь всё…»**
5. Получится папка **`PixelBridge-main`**. Можете переименовать её в
   `PixelBridge` — на работу не влияет

Это прямая ссылка на тот же архив, если удобнее:
<https://github.com/AGNARE/PixelBridge/archive/refs/heads/main.zip>

### Способ Б — через git

Нужен установленный Git. Откройте терминал в папке, где будет лежать проект:

```bash
git clone https://github.com/AGNARE/PixelBridge.git
cd PixelBridge
```

**Проверка, что скачалось то, что нужно.** В папке должны лежать:

```
manifest.json        ← его вы будете выбирать в Figma
start-engine.cmd     ← его вы будете запускать
engine/
skills/
code.js
ui.html
```

Если `manifest.json` на месте — всё скачалось правильно.

> **Не распаковывайте проект куда-то временно.** Figma запоминает путь к
> `manifest.json`. Если потом перенести или удалить папку, плагин перестанет
> запускаться, и его придётся подключать заново.

## Шаг 2. Поставить Node.js

Проверьте, не стоит ли уже. Откройте терминал (**Windows:** `Win+R` →
`cmd` → Enter) и выполните:

```bash
node --version
```

- Показало `v20.x` или `v22.x` и выше — **всё есть**, переходите к шагу 3.
- Написало «команда не найдена» / «is not recognized» — ставьте.

Установка: скачайте **LTS**-версию с <https://nodejs.org> и установите со
стандартными настройками (все галочки по умолчанию). После установки
**закройте и откройте терминал заново** — иначе команда `node` не найдётся,
это самая частая мелкая заминка. Проверьте `node --version` снова.

## Шаг 3. Запустить движок

Движок — это программа на вашем компьютере. Она рендерит страницы и
обслуживает плагин. Пока она не запущена, плагин работать не будет.

### Windows

Двойной клик по **`start-engine.cmd`** в папке проекта.

Откроется окно консоли с журналом. В нём будет адрес движка и подсказки.

> **Это окно должно оставаться открытым** всё время, пока вы работаете с
> плагином. Закрыли окно — движок выключился.

Если Windows показывает предупреждение о неизвестном файле (так бывает с
файлами из интернета) — нажмите «Подробнее» → «Выполнить в любом случае».
Либо снимите блокировку заранее: правый клик по `start-engine.cmd` →
**Свойства** → галочка **«Разблокировать»** → ОК.

### macOS и Linux

Файлы `.cmd` — только для Windows. Запускайте движок напрямую, из папки
проекта:

```bash
node engine/server.js
```

## Шаг 4. Подключить плагин в Figma

Делается **один раз**. Дальше плагин останется в списке разработки навсегда.

1. Откройте **Figma Desktop** (приложение, не сайт в браузере)
2. Меню **Plugins → Development → Import plugin from manifest…**
3. В открывшемся окне выберите файл **`manifest.json`** из папки проекта
4. Запустите плагин: **Plugins → Development → Web → Figma Bridge**

> Если в меню **Plugins** нет пункта **Development** — вы в браузерной версии
> Figma. Плагины разработчика и доступ к локальному движку есть только в
> настольном приложении.

---

## Шаг 5. Проверить, что всё работает

Порядок проверки — от движка к плагину, чтобы сразу видеть, что именно не так.

**1. Движок.** Откройте в браузере <http://127.0.0.1:7331> — должна открыться
страница состояния с журналом. Или в терминале:

```bash
curl http://127.0.0.1:7331/health
```

**2. Плагин.** Откройте окно плагина в Figma. В шапке должен гореть
**зелёный индикатор**, а в журнале — строка «Плагин запущен. Движок:
http://127.0.0.1:7331».

**3. Импорт.** Вкладка **«Сайт»** → вставьте `https://example.com` → нажмите
**«Импортировать в Figma»**. На холсте появится выделенный фрейм.

Всё три пункта прошли — установка закончена.

## Если вы даёте ссылку другому человеку

Ничего копировать и передавать не нужно. Отправьте ссылку на репозиторий:

```
https://github.com/AGNARE/PixelBridge
```

Человек проходит **эту же инструкцию** у себя: скачивает файлы, ставит
Node.js, запускает движок, подключает плагин. Никакой общей инфраструктуры
между вами нет:

- **Движок у каждого свой.** Он слушает `127.0.0.1` — это адрес «этот
  компьютер». Снаружи, из сети, он недоступен никому, включая вас.
- **Figma-файлы у каждого свои.** Плагин пишет в тот файл, который открыт у
  него, и только пока он сам его запустил.
- **Данные не смешиваются.** Ваши захваченные страницы, кэш и профиль
  остаются у вас, его — у него.

Поэтому «отдать инструмент» = «отдать ссылку». Аккаунтов, ключей и общих
серверов в проекте нет.

## Как обновить версию

**Если ставили через git:**

```bash
cd PixelBridge
git pull
```

**Если ставили через ZIP:** скачайте архив заново (шаг 1) и распакуйте поверх
старой папки, заменив файлы. Или распакуйте рядом и перенесите нужное.

**После обновления:**

1. Перезапустите движок — закройте окно `start-engine.cmd` и запустите заново,
   иначе работает старая версия кода
2. В Figma плагин перезапустите (**Plugins → Development → Web → Figma
   Bridge**). Заново импортировать `manifest.json` не нужно — путь тот же

Если вы пользовались скиллами для ИИ-агента, обновите и их:

```
install-skills.cmd
```

## Как полностью удалить

Инструмент не прописывается в систему и не оставляет служб. Убрать его —
значит удалить четыре вещи:

1. **Папку проекта** — просто удалите её
2. **Профиль браузера**, если включали режим «постоянный» — папка
   `engine/.profile` внутри проекта, уйдёт вместе с ним. Там ваши куки, так
   что удаляйте осознанно
3. **Плагин из Figma** — правый клик по нему в списке
   **Plugins → Development** → **Remove plugin**
4. **Скиллы, если ставили** — удалите папки `figma-bridge` и `ux-ui-design` из
   `%USERPROFILE%\.dsh\skills\` и `%USERPROFILE%\.agents\skills\`

Node.js удалять не нужно — он общий и, скорее всего, вам ещё пригодится.

## Если что-то не получилось

**`start-engine.cmd` открывается и мгновенно закрывается**
Значит внутри ошибка. Запустите вместо двойного клика явно: откройте терминал
в папке проекта и выполните `start-engine.cmd` — окно останется, и текст
ошибки будет виден. Чаще всего это не установленный Node.js (шаг 2).

**`node` не найден, хотя Node.js установлен**
Закройте и откройте терминал заново — путь к `node` подхватывается при старте.
Если не помогло, переустановите Node.js и перезагрузитесь.

**`The syntax of the command is incorrect` при запуске `.cmd`**
Файл запускалки повреждён при копировании (например, если вы копировали текст
руками). Скачайте ZIP заново — в архиве запускалки лежат в правильном формате.

**Windows не даёт запустить `.cmd`**
Снимите блокировку: правый клик → **Свойства** → **«Разблокировать»** → ОК.

**Движок пишет, что порт 7331 занят**
Запустите на другом порту:
```
set W2F_PORT=7444
start-engine.cmd
```

**«Не найден Chrome или Edge»**
Укажите путь вручную:
```
set W2F_BROWSER=C:\путь\к\chrome.exe
start-engine.cmd
```

**В Figma нет пункта Development**
Вы в браузерной версии. Нужно настольное приложение Figma.

**Индикатор в плагине жёлтый, «движок не запущен»**
Окно движка закрыто. Вернитесь к шагу 3.

**Агент говорит, что мост недоступен**
Проверьте <http://127.0.0.1:7331/health>. `ok:false` — не запущен движок,
`plugin:false` — не открыто окно плагина. Нужны обе вещи одновременно.
